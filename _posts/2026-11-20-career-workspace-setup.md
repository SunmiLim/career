일한 과정을 꾸준히 남겨 두었다가, 나중에 블로그 글이나 카드뉴스, 영상으로 다듬어 보고 싶었습니다.
그래서 오늘은 기록을 담아 둘 공간부터 만들었습니다.

## AI 브라우저 대신 GitHub를 골랐습니다

처음에는 웹 작업을 대신해 주는 AI 브라우저를 설치해 볼까 고민했습니다.
작업이 끝난 뒤 글을 올리는 일 같은 잔처리를 맡길 수 있다고 해서였습니다.

그런데 기능을 하나씩 따져 보니, 제가 필요한 것은 웹을 대신 클릭해 주는 도구가 아니었습니다.
**기록을 꾸준히 쌓고, 그 기록을 글로 바꾸는 흐름**이 먼저였습니다.

그래서 글을 네이버나 인스타그램이 아니라 GitHub에 올리기로 했습니다.
마크다운 파일로 글을 쓰고 올리면 GitHub Pages가 블로그로 보여 줍니다.
게시가 곧 파일 업로드라서, AI 코딩 도구로 기록 정리부터 게시까지 한 흐름으로 이어갈 수 있습니다.

## 공개용과 비공개용을 나눴습니다

가장 먼저 정한 것은 **원본 기록과 공개 글을 분리하는 것**이었습니다.

- **비공개 저장소**: 날짜별 업무 로그, 카드뉴스 문안, 영상 대본 초안
- **공개 저장소**: 다듬어서 보여 줘도 되는 글만 올리는 블로그

업무 기록에는 밖에 내보이면 안 되는 내용이 섞이기 쉽습니다.
처음부터 공간을 나눠 두면 "이건 올려도 되나?"를 한 번 더 생각하게 됩니다.

작업 폴더는 학교 클라우드 드라이브가 아니라 개인 PC의 내장 디스크에 두었습니다.
클라우드 동기화는 git 저장소와 충돌할 수 있고, 소속이 바뀌면 계정에 접근할 수 없게 될 수도 있기 때문입니다.
영상 원본처럼 큰 파일은 외장하드에 따로 보관하기로 했습니다.

## 기록은 다섯 가지만

로그는 매번 같은 형식으로 짧게 남깁니다.
**무엇을** 했고, **왜** 했고, **결과**가 어땠고, **막힌 점**은 무엇이었고, 어떤 **도구**를 썼는지.
형식이 정해져 있으니 쓰는 부담이 줄고, 나중에 다시 꺼내 쓰기도 쉽습니다.

## 막혔던 점

PC에 git 명령 도구가 설치되어 있지 않아 처음 계획대로 진행되지 않았습니다.
우선은 이미 있던 GitHub Desktop을 활용하고, 저장소는 웹에서 직접 만들어 첫 공간을 완성했습니다.

그 뒤에 Git과 GitHub CLI를 정식으로 설치했습니다.
여러 작업에 쓰던 GitHub 계정이 모두 같은 계정인지도 확인해서, 기록 저장소도 그 계정으로 통일했습니다.
꼭 처음 생각한 방법이 아니어도 있는 도구로 먼저 끝까지 가 보고, 부족한 부분은 나중에 채우면 된다는 걸 다시 느꼈습니다.

## 다음에 할 것

이제 일이 끝날 때마다 짧게라도 로그를 남겨 보려고 합니다.
어느 정도 쌓이면 어떤 형식(블로그, 카드뉴스, 영상)이 가장 잘 맞는지도 정해 보겠습니다.
